### [TEL-00057] cli: land the drone when the program fails
- **Status:** ✅ Выполнена
- **Complexity:** 5
- **Description:** Требование владельца: программа стабильна, а при критической ошибке до последнего
  шлёт дрону команду на посадку. Сейчас: аварийный сигнал / `std::terminate` / фатальное исключение
  в `main` только пишутся в журнал, дрон остаётся висеть (сядет сам через 15 с без команд);
  `exit`, Ctrl+D и закрытие терминала в воздухе выходят, не сажая дрон.
  Сделать:
  1. Флаг «в воздухе» и заранее открытый UDP-сокет с адресом дрона доступны из обработчика сигнала.
  2. SIGSEGV/SIGABRT/SIGFPE/SIGBUS/SIGILL/SIGTERM/SIGHUP/SIGQUIT и `std::terminate` в воздухе:
     `rc 0 0 0 0`, затем `land` 3 раза с паузой ~100 мс (только async-signal-safe `sendto`/`nanosleep`),
     запись в журнал, затем обычная смерть процесса.
  3. Фатальное исключение в `main` в воздухе: обычный `land` с ожиданием ответа, потом выход.
  4. `exit` / `quit` / Ctrl+D / конец входа в воздухе: сначала `land`, выход только после посадки
     (если посадка не прошла — сказать и остаться в оболочке; в режиме канала — выйти с кодом ошибки).
  5. Сторож зависания: если команда в главном потоке не завершается дольше своего предела
     (таймаут ответа + запас; `wait` и фигуры — по их плановому времени), keepalive перестаёт
     держать дрон и шлёт `land` — иначе зависшая программа держит дрон в воздухе бесконечно.
  Не покрывается: `kill -9`, выключение ноутбука, потеря Wi-Fi — там выручает собственная
  автопосадка Tello через 15 с без команд.
  Тесты на симуляторе: сигнал в воздухе (дочерний процесс `tello`) → симулятор приземлён; `exit`
  в воздухе → `land` в журнале и симуляторе; зависшая команда → посадка от сторожа.

### [TEL-00056] cli: flight log for post-flight analysis
- **Status:** ✅ Выполнена
- **Complexity:** 5
- **Description:** Владелец летает без интернета и ИИ, разбирает полёт потом. Сейчас логов нет
  (только история строк `~/.tello_history`). Каждый запуск `tello` пишет файл
  `~/.local/state/tello/logs/tello_ДАТА_ВРЕМЯ.log` (текст, одна запись на строку, время с мс):
  версия, модель, хост/порты, настройки; каждая введённая строка и строка миссии; каждая SDK-команда
  дрону и ответ / таймаут с задержкой в мс (декоратор над `ITransport` в CLI, библиотека не печатает);
  keepalive — только сбои; ошибки и исключения; события безопасности (предупреждение и автопосадка
  по батарее, Ctrl+C в воздухе, `emergency`, прерывание фигуры); старт/конец фигуры и миссии,
  пути сохранённых фото/видео/mp4; снимок телеметрии раз в 1 с в воздухе (bat, h, tof, темп., скорости,
  оценка позиции); потеря и возврат телеметрии и видео. Файл сбрасывается на диск после каждой
  записи (переживает падение). Хранятся последние `log_keep` (30) файлов. Ключ `--log-dir`, конфиг
  `log_dir` / `log_keep`, `--no-log`; команда `log` печатает путь текущего файла. Тест: сессия против
  симулятора — в логе есть команды, ответы, телеметрия; ротация. Руководства (6 языков) — раздел про журнал.
